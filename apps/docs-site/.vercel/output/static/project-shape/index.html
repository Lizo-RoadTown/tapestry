Every project develops
a personality.

Some projects become easier to work in. Others become harder. The code may barely change — but suddenly everyone knows how things work, decisions are easier to make, and agents stop needing the same corrections over and over.

Or the opposite happens. Knowledge fragments. Workflows drift. Context disappears. The same mistakes keep coming back.

Learn about project shape → Watch it move →

Most tools only see the code. Tapestry tracks the things that make a project easier or harder to work in over time. We call that project shape.

  • →how knowledge is stored
  • →how agents behave
  • →how work gets done
  • →what corrections keep recurring
  • →what skills become reusable
  • →where coordination breaks down

Because those things often determine project success long before the code does.

Why it matters

Same repository.
Different outcome.

Two projects can have identical repositories and completely different outcomes. One feels predictable. The other feels chaotic. The difference is rarely the code itself — it's the accumulated decisions, habits, corrections, workflows, and knowledge surrounding it.

Those patterns determine whether:

  • →new contributors ramp up quickly
  • →agents make the same mistakes repeatedly
  • →knowledge survives between sessions
  • →workflows improve over time
  • →coordination scales as complexity grows

Tapestry makes those patterns visible.

What changes over time

A few patterns keep appearing.

As projects evolve, the same handful of motions show up again and again.

Things drift

The project behaves differently than everyone expects. Agents need more corrections. Knowledge becomes harder to find.

Things stabilize

The same corrections stop appearing. Workflows become predictable. The project becomes easier to operate.

Things fragment

Different parts of the project develop conflicting assumptions. Knowledge gets duplicated. Coordination becomes harder.

Things come together

Previously disconnected workflows, knowledge, and practices start reinforcing each other. The project becomes more coherent.

The observer tracks these changes so they can be understood before they become problems.
