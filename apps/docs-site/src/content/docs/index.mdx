## Who this is for

You are creating a project that plugs into the Tapestry platform — for example, the way SDE_Extraction plugs in. You want the agent working in your project to behave like the agent working in `the-loom` or `Make_Skills`: it checks memory at the start of a task, follows PROBE discipline, knows what's a runtime concern vs a dev-tooling concern, and writes friction to memory the moment you correct it.

You do not need to know every internal mechanic. You need to know which files are load-bearing, what each one does, and how to recover when one of them goes missing.

## What this site explains

- The stack of plugins, MCP wiring, hooks, and configuration files that make the agent in your project behave like the agents in Liz's other projects.
- Why each piece exists. (If you don't know what something does, you will eventually delete or move it. Knowing why prevents that.)
- How to set up a new project so the stack is wired correctly from day one.
- How to recover when the agent starts drifting — usually because something small went missing.

## What this site does NOT cover

- What Tapestry IS conceptually. That lives in the [MANIFESTO](https://github.com/Lizo-RoadTown/tapestry/blob/main/MANIFESTO.md) and the [architecture umbrella](https://github.com/Lizo-RoadTown/tapestry/blob/main/docs/architecture/UMBRELLA.md).
- How Tapestry is built. That lives in the migration docs and ADRs inside the repo.
- API references for the platform services. Those come later when the services migrate from `the-loom` into Tapestry.
