## Why it matters

The CLI is the entry point for consuming-project onboarding. `loom init --slug <name>` does five things in sequence:

1. Warms the project-registry Render service (cold-start tolerance built in).
2. POSTs a new project row; idempotent on rerun.
3. Writes `.env` with `LOOM_PROJECT_ID` + propagated OTel credentials from the operator's `the-loom/.env`.
4. Writes or merges `.mcp.json` with the `loom-memory` HTTP server entry (described in `init.py:214-271` as "Layer 5" of the concrete-rule defense-in-depth pattern).
5. Initializes `.project-intelligence/` with `agent-profile.json`, `project-context.json`, `observatory-config.json`, and four subdirectory stubs.

The stdlib-only constraint (`dependencies = []` in `pyproject.toml:17`) means `pip install loom-cli` works on any Python 3.10+ without model downloads or compiled wheels — important for the cross-platform `loom init` promise stated in the README.

The URL resolution for `LOOM_MEMORY_MCP_URL` in `init.py:204-210` handles a four-deep env-var precedence chain (`TAPESTRY_MEMORY_MCP_URL` → `LOOM_MEMORY_MCP_URL` → `TAPESTRY_MEMORY_URL` → `LOOM_MEMORY_URL`) so both Tapestry-aware and pre-Tapestry consuming projects get the right endpoint without code changes.

Status per `import-map.md:43`: "Imported (Step 5a, 2026-06-21) — not published yet." Publishing is explicitly deferred; the package name `loom_cli` is also held pending a rename decision (same pattern as `loom_auth` from Step 1).

## Diagnosis (drift, risks, things to verify)

**`loom init` requires `the-loom/render.yaml` to exist** (`init.py:367-370`). The loom-repo detection check fails silently if the operator's `the-loom` checkout is absent or at a non-default path. The only recovery path currently is `--loom-repo` or `LOOM_REPO` env var. This is a usability gap for new adopters who don't have the parent repo checked out — not a bug, but worth noting in future onboarding docs.

**OTel credential propagation reads `the-loom/.env` at runtime** (`init.py:51-71`). If that file is absent (CI, clean machine, new adopter), `.env` is written without OTel keys and only a WARN is printed (`init.py:418-420`). The project gets `LOOM_PROJECT_ID` but no telemetry wiring. No error is surfaced at install time.

**`packages/cli/pyproject.toml:23-24` still points at `the-loom` GitHub URLs**, not the Tapestry repo. After publish, `pip show loom-cli` and PyPI will link to the prototype source. Low risk now (not published), but needs updating before any distribution.

**No test files included in this lift.** The README (`packages/cli/README.md:8`) lists only the four source files as lifted. `the-loom/loom-cli/` may have had tests; if so, they weren't included. Not confirmed — worth a check against source before Step 5a is considered complete.

**`packages/cli` has 0 declared dependencies but the snapshot's `python.total_package_count` is 25** (all in other manifests). The snapshot's `package_count: 0` for `packages/cli/pyproject.toml` is correct — this is expected, not a parsing error.
